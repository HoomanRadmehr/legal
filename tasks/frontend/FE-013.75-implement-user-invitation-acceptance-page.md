## Goal

Allow an invited user to set their own password through a public, localized invitation-acceptance page.

The page does not automatically authenticate the user after success.

## Route and token handling

Use:

```text
/accept-invitation#token=<signed-token>
```

The token is read from the URL hash fragment and sent only to the invitation acceptance endpoint. It is never rendered, logged, stored, or copied into browser persistence.

## API contract

```text
POST /api/v1/auth/invitations/accept/
```

Request body:

```json
{
  "token": "<signed-token>",
  "password": "<new-password>",
  "password_confirm": "<new-password>"
}
```

## Implementation steps

1. Add typed invitation acceptance API function and mutation hook.
2. Add an explicit public `/accept-invitation` page that reads `token` from the hash fragment.
3. Add a localized password and confirmation form using React Hook Form and Zod.
4. Submit token and passwords to `POST /auth/invitations/accept/`.
5. Show generic invalid-invitation errors and safe rate-limit guidance.
6. Show success without creating a frontend session or redirecting automatically.
7. Add focused tests for public route behavior, token handling, validation, errors, no token persistence, and Persian RTL rendering.

## Acceptance criteria

- [x] `/accept-invitation#token=<signed-token>` renders without an authenticated session.
- [x] Missing token shows a safe error and does not submit.
- [x] The request sends `token`, `password`, and `password_confirm` only.
- [x] Password confirmation is validated before submit.
- [x] Invalid, expired, already-used, or unknown invitations show one generic message.
- [x] `429` responses show retry guidance using `Retry-After`.
- [x] Success tells the user to sign in and does not create an auth session.
- [x] English and Persian labels render, with RTL direction in Persian.
