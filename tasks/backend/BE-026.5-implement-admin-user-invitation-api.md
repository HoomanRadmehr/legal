## Goal

Allow a Legal Admin to create a new organization user securely without choosing the user's password.

The operation creates:

- an inactive User,
- an organization Membership,
- a pending UserInvitation,
- an append-only activity record,
- a transactional outbox event for the invitation email.

The organization is always derived from the authenticated Admin's active membership.

## Business rules

1. Only an active `legal_admin` membership may create organization users.
2. The request must never accept `organization_id`.
3. The Admin must not provide a password.
4. The new User is initially created with:
   - `is_active=False`,
   - an unusable password,
   - normalized email,
   - canonical preferred language.
5. The Membership uses one of:
   - `legal_admin`,
   - `legal_manager`,
   - `legal_counsel`,
   - `viewer`.
6. The Membership belongs to the Admin's current organization.
7. The Membership may use the existing `active` status because the inactive User cannot authenticate or appear in active-user selectors.
8. Owner and assignee selectors must continue to require an active User and active Membership.
9. Duplicate email addresses return a stable `409` error.
10. No invitation token is stored in plaintext.
11. No invitation URL or token is written to application logs, audit metadata, or outbox payloads.
12. Invitation email is a mandatory transactional email and does not depend on user notification preferences.
13. Hard deletion is not added.
14. The operation supports `Idempotency-Key`.
15. Reusing an idempotency key with different input returns `409`.
