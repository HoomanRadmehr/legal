# MinIO presigned document flow

## Storage boundary

Django stores document metadata; MinIO stores bytes.
The bucket is private and object keys are generated by the backend.

Server-side MinIO operations use `MINIO_INTERNAL_ENDPOINT` or the existing
`MINIO_ENDPOINT` compatibility value. Browser-facing upload and download URLs are
signed for `MINIO_PUBLIC_ENDPOINT` and are not host-rewritten after signing. The
signing client uses `MINIO_REGION` so presign creation does not need to probe the
browser-facing endpoint from inside the API container.

## Initiate endpoint

```text
POST /api/v1/documents/presign/
Idempotency-Key: <uuid>
```

Input:

```json
{
  "matter_id": "uuid",
  "filename": "notice.pdf",
  "content_type": "application/pdf",
  "size": 1048576,
  "checksum_sha256": "optional-lowercase-sha256"
}
```

The service:

1. Resolves the visible editable matter.
2. Enforces role and matter permission.
3. Validates extension, content type, size, organization quota if enabled, and active upload count.
4. Creates a backend-owned key such as `organizations/<org>/matters/<matter>/documents/<document-id>`.
5. Creates a `Document(status=pending_upload)` with expiry.
6. Returns short-lived presigned instructions.

Output includes the document ID, method, URL, required headers, and expiry.
The URL is never persisted in PostgreSQL.

## Client upload

The browser sends bytes directly to MinIO and displays local progress.
MinIO CORS allows only the frontend origin and required methods/headers.
Local browser development uses `http://localhost:9000` as the public endpoint.
Compose integration tests may use `http://minio:9000` so the test container can
reach the same final host that was signed.

## Completion endpoint

```text
POST /api/v1/documents/{document_id}/complete/
```

The service verifies:

- document belongs to the authenticated organization;
- the current user still has edit permission on the matter;
- status permits completion;
- pending upload has not expired;
- object exists at exactly the expected key;
- size matches expected size;
- content metadata is acceptable;
- checksum matches when a supported trustworthy checksum is available;
- the document is not already failed, expired, or cancelled.

It marks the document `verifying`, writes safe activity/outbox data, then marks it `available`.
Repeated completion for an already available document returns the same document without duplicate events.
No antivirus claim should be made unless a scanner is actually integrated.

## Download

```text
POST /api/v1/documents/{document_id}/download-url/
```

After permission and status checks, return a short-lived GET URL.
Audit the download request, not the URL itself.

## Cleanup

Celery Beat marks expired pending documents and removes abandoned objects according to a simple safe policy.
Cleanup is idempotent and does not touch available documents.
