# Documentation index

The documentation is organized by purpose so an implementation agent can load only the context required for one task.

## Business

Product purpose, terminology, roles, workflows, domain rules, and the MVP boundary.
Start with `business/06-mvp-scope.md`.

## Guardrails

Rules that cannot be traded away for speed: simplicity, security, tenancy, API behavior, testing, realtime, localization, and AI-agent behavior.

## Tech

Approved technical design for backend, frontend, data, JWT, uploads, realtime, Celery, notifications, OpenAPI, environment settings, Docker, observability, and dependencies.

## Decisions

Accepted architecture decision records. A task may not silently contradict an accepted ADR.

## Templates

Use these when adding a new spec, task, ADR, or review record.

## Traceability

Stable requirement IDs, mapping to specs, and the shared definition of done.
